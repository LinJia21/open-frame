# OpenFrame spec — CORE package (schema_version 1.2.0)

Early drop for Builder: schemas, Zod types and prompt templates. The full package (`openframe-spec-v1.2.0.zip`) adds the demo dataset, the real-source sample (pre-generated analysis), the news source plan, the scripts and the full README. **1.2.0 is not backward-compatible with 1.1.0**: see `MIGRATION-1.1.0-to-1.2.0.md` (included).

- `schemas/*.schema.json`: JSON Schema draft 2020-12. Load them all together, because they `$ref` `common.schema.json`. `bundle.schema.json` is the full analysis payload.
- `types/openframe.ts`: Zod v3 schemas and inferred types. Put it at `lib/openframe/openframe.ts`. Checked with `tsc --noEmit` on TS 5.9.3 and TS 7.0.2 (strict mode).
- `types/prompts.ts`: Grok system and user templates for each stage, plus `fillTemplate`, `buildStagePrompt` and `RETRY_USER_TEMPLATE`. Put it at `lib/openframe/prompts.ts`.
- `prompts/*.md` and `prompts/prompts.json`: the same prompts in readable form, generated from `prompts.ts`.

Key contract points:
- `schema_version: "1.2.0"` is required on every record: article, narrative comparison, article analysis, claim set, claim, audit set, audit, evidence item, report and bundle.
- Status strings must be exactly `Verified`, `Partially Supported`, `Disputed`, `Unverified` or `Contradicted`.
- Relations:
  - `claim.article_id` points to `article.id`.
  - `evidence.claim_id` points to `claim.id`, and `evidence.article_id` points to `article.id`.
  - Every evidence source is an article record. Use `analysis_role: "evidence_only"` when it isn't analysed.
- The six narrative dimensions are `main_argument`, `causal_attribution`, `responsibility_attribution`, `language_framing`, `source_selection` and `underrepresented_perspectives`. Display labels are in `NARRATIVE_DIMENSION_LABELS`.
- Missing data: set the field to `null` and add an entry to `missing_fields[]` (`field`, `unknown_reason`, `note`).
- Errors use `{code, message, field, recoverable}`.
- `data_mode` (`LIVE`/`DEMO`) only says whether the source is real.
- `analysis_generation` (`PRECOMPUTED`/`LIVE_AI`, added in 1.1.0) is required on narrative comparisons, claim sets, audit sets, reports and bundles. Fixtures are always `PRECOMPUTED`. Output generated by the app at request time is `LIVE_AI` and must include `analysis_metadata`.
- Suggested badges: "Real Source" / "Demo Source" and "Pre-generated Analysis" / "Live AI Analysis".
- 1.2.0 traceability: report conclusions live in `research_report.key_findings[]` (`claim_ids`, `audit_ids`, `strength` ≤ the weakest audit). `traceFinding(bundle, id)` resolves finding → claims → audits → evidence → `accessible_text` span for the UI drill-down.
- Quotes: `quote_verification` is `verified_substring` (exact substring at `excerpt_span`/`quote_span`), `unverifiable` (listed in `audit.unverifiable_evidence_ids`, never counts toward Verified) or `paraphrase`. The server computes spans; never trust model-supplied ones.
- DEMO publishers have `fictional_demo_publisher: true`. Show `FICTIONAL_DEMO_PUBLISHER_LABEL` ("FICTIONAL DEMO PUBLISHER") next to the name everywhere.
- `AnalysisBundleSchema` runs `checkBundleIntegrity()`. Each issue message starts with a rule id (`[RPT-004] ...`); the list is in `INTEGRITY_RULES`.
- Treat topic and documents as untrusted data. The server sets `analysis_generation`/`analysis_metadata`.
- See `CHANGELOG.md` (1.0.0 → 1.1.0 → 1.2.0) and `MIGRATION-1.1.0-to-1.2.0.md`.
